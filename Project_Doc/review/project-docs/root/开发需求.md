## 2. 统一产品目标

### 2.1 产品定位

HelpSupport 是一款面向医院内小规模部署的治疗支持 App，用于成瘾行为改变、情绪支持、治疗计划执行与康复陪伴。

### 2.2 目标用户

- 患者：接受 AI 支持、执行治疗计划、进行社区互助、记录日记、预约真人医生。
- 医生/治疗师：管理患者、配置治疗计划、审核社区内容、提供预约服务、维护专业身份。
- 管理员/后台运营：审核医生资质、维护内容、管理任务模板、素材、预约资源与系统配置。

### 2.3 产品原则

1. 默认面向海外用户，正式上线版本必须支持英文界面。
2. 设计稿中的中文文案视为原型占位，开发时需统一走 i18n 文案体系。
3. 日记与离线陪伴数据需明确区分本地数据与云端数据边界。
4. 产品需同时覆盖患者端、医生端、后台管理端。

## 4. 角色与权限

### 4.1 患者

- 使用 AI 心理医生、AI 心理陪伴、AI 模拟病人
- 选择在线模式或本地模式
- 查看、编辑、执行治疗计划
- 接收计划提醒与消息通知
- 发布社区内容、评论、回复、点赞、收藏、关注
- 查看教育素材、娱乐内容、私人素材
- 撰写本地日记
- 管理个人资料、隐私设置、成长体系、回忆录
- 预约真人医生

### 4.2 医生/治疗师

- 完成医生身份注册与资格证书上传
- 管理个人资料与职业资质
- 维护患者列表，添加/移除患者
- 为患者配置治疗计划、阶段、任务模板、评估量表
- 查看患者任务完成度与阶段进度
- 审核社区内容
- 发布带医生标识的社区内容
- 接受患者预约

### 4.3 管理后台

- 审核医生资质
- 管理教育素材、娱乐内容、私人素材分类配置
- 管理治疗阶段、计划、任务模板、评估量表
- 管理医生预约排班与价格
- 审核社区举报与敏感内容
- 查看聊天配置、计划执行、预约记录等后台数据

## 5. 详细功能需求

## 5.1 启动、登录与注册

### 5.1.1 启动页

- App 启动时展示品牌 Splash 页。
- 启动页之后进入登录或注册流程。

### 5.1.2 登录

- 支持邮箱/手机号 + 密码登录。
- 支持忘记密码。
- 首次登录需勾选条款清单和隐私政策。
- 支持根据来源页回跳。

### 5.1.3 注册分步流程

患者与医生共用以下前置步骤：

1. 输入邮箱
2. 输入验证码
3. 设置密码
4. 填写个人资料

### 5.1.4 身份分流

- 用户在注册资料页选择身份：患者 / 医生。
- 选择患者后直接完成资料填写。
- 选择医生后进入证书上传流程。

### 5.1.5 医生资格认证

- 医生必须上传资格证书图片。
- 支持重新上传、替换。
- 后台需有审核状态：待审核 / 通过 / 驳回。
- 未通过审核前，医生账号不可使用医生专属能力。

### 5.1.6 资料初始化

注册阶段至少采集以下信息：

- 账号名称
- 性别
- 出生日期
- 身份
- 医生证书（医生必填）

### 5.1.7 会话安全

保留原始需求中的以下能力：

- 单端在线限制（可配置）
- 手动下线其他设备
- 登录态失效处理

## 5.3 AI 互动聊天

### 5.3.1 模式列表

系统需提供三种聊天模式：

- AI 心理医生
- AI 心理陪伴
- AI 模拟病人

每种模式均需提供模式介绍信息与开始体验入口。

### 5.3.2 在线/本地模式选择

`心理陪伴` 与 `模拟病人` 需支持：

- 在线模式
- 本地模式

本地模式的数据原则：

- 会话数据默认保存在本地
- 模型运行在设备端
- 用户可自行管理模型下载与删除

### 5.3.3 个性化定制

在进入陪伴类聊天前，支持填写个性化设定：

- AI 扮演对象
- 描述与要求
- 可预设角色方向，例如朋友、伴侣、动物等

说明：

- 该部分在在线模式下可上传服务器作为系统 prompt。
- 本地模式下应支持仅设备本地保存。

### 5.3.4 本地模型管理

设计稿已体现独立的“本地模型”页面，需补充为正式需求：

- 支持搜索模型
- 支持全部 / 已下载 / 未下载筛选
- 支持下载、删除、查看当前状态
- 模型下载状态需要持久化

### 5.3.5 会话页能力

聊天页至少支持：

- 文本消息
- 语音消息
- AI 文本回复
- AI 语音回复
- Markdown 基础渲染
- 顶部快捷入口：会话信息 / 实时通话

### 5.3.6 语音/实时通话

保留原始需求，并补充 UI 入口要求：

- 非实时语音消息
- 麦克风实时通话
- 可扩展至摄像头实时会话
- 语音消息支持播放/暂停

### 5.3.7 消息操作

设计稿显示消息长按后存在操作栏，需补充为正式需求：

- 撤回
- 复制
- 删除
- 分享
- 转文字

### 5.3.8 会话历史管理

- 首页展示最近对话。
- 支持进入历史会话。
- 支持删除单个会话并二次确认。
- 会话自动命名，如“第一次访问”“第二次访问”。

### 5.3.9 AI 任务建议卡

AI 在对话中可返回任务建议卡，卡片至少包含：

- 任务名称
- 优先级
- 来源
- 时间
- 分数
- 查看详情入口

任务卡支持一键加入患者计划日历。

### 5.3.10 数据边界

- 在线 AI 会话可上传服务器并用于后续计划、回忆录生成。
- 本地模式数据默认不上传服务器。
- 日志与隐私边界必须在设置和隐私协议中明确。

## 9. 本次重整后的结论

1. `PRD.md` 已将原始需求结构化，但仍停留在模块级说明，无法直接覆盖设计稿中的完整交互流。
2. 当前 UI 设计稿实际已经定义了不少“二级流程”和“状态页面”，尤其是认证、AI 模式、计划模板、评估量表、预约和医生端功能，这些都必须进入正式需求。
3. 新需求应以“患者端 + 医生端 + 后台支撑”一体化方式推进，而不是只写患者功能。
4. 开发时必须同步引入英文国际化方案，否则与“海外产品”目标不一致。 先不管！
